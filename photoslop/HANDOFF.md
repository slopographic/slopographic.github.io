# PhotoSlop: handoff

A layered, Photoshop-style image editor at `/photoslop/` (`/paint/` redirects here; `paint/classic/` is the separate MS Paint clone, still served from `photoslop/classic/`, leave it alone). Plain classic scripts loaded in order from `index.html`, sharing top-level names. Every file is at most 300 lines.

## Layout
- `js/core/`: helpers (`util.js`), document model and history (`model.js`: `D`, `Hist`, `commit`, `undo`), compositing, document ops (`ops.js`), image and canvas size with resampling (`size.js`), the viewport (`view.js`: zoom/pan, drawing, pointer routing).
- `js/tools/`: tool registry and selection/move/crop (`select.js`), painting, fills/shapes/type, free transform.
- `js/guides/`: rulers, guides, grid and snapping (see below).
- `js/brushes/`, `js/filters/`, `js/io/` (PSD, ORA, other formats, autosave in IndexedDB, offline single-file build, Slop Hub).
- `js/ui/`: menus (`menus.js`: `MENUS`), menubar/toolbox/options (`chrome.js`), panels, dialogs, keyboard (`doc-dialogs.js`), Image Size and Canvas Size (`size-dialogs.js`).
- `js/app/`: tabs (multiple documents), `commands.js` (SlopCmd), `main.js` (boot).

## Theme tokens (`css/layout.css`, `css/extras.css`, `shared/theme/theme.js`)
- The shared switcher (System, Light, Dark, Classic 98, Slopographic Lime) paints `data-slop-theme` and the `--sl-*` variables on `<html>`: `--sl-background`, `--sl-surface`, `--sl-text`, `--sl-accent`, `--sl-border`, `--sl-on-accent`. The app's chrome tokens are defined from those in one block, `html:root[data-slop-theme]`, with a Classic override block `html:root[data-slop-theme=classic]`. Nothing in the chrome is hard-coded; `[data-theme="pro|light|paint"]` blocks are only the fallback when the shared script is missing.
- Chrome tokens: `--app` (page and main area) and `--bar` (menu bar, top bar, status bar) = background. `--chrome` (toolbox, tabs, panels, drop strip) = surface; Classic = background. `--panel-2` (options bar, panel headers, menus, buttons) = surface 90% text; Classic = background. `--panel-3` (active tab, chips, active button) = surface 80% text. `--line` = border; `--line-2` = border 60% text.
- Text: `--fg` = text (set by theme.js); `--fg-dim` = text 76% over surface (labels, options bar names); `--fg-faint` = text 80% (units, meta; set by theme.js). `--hover` and `--active` are mixes of surface and text.
- Selection: `--sel` (selected layer, menu row, current history step) = accent 28% over surface; Classic = accent. `--sel-ink` is the text on it: text, or on-accent in Classic.
- Accent: `--accent` and `--accent-ink` (set by theme.js); `--accent-2` = accent 70% over surface (the second stop of the Classic title bars and panel headers).
- Fields and wells: `--input` = surface (number boxes, select, layers and history lists in Classic). `--pasteboard` = background 84% text (Classic: border). `--focus` = accent.
- Fixed on purpose (document and canvas content, not chrome): the canvas, the transparency checkerboard, layer mask thumbnails, colour swatches (`.sw-*`, `.swatch`), the mask-off slash.
- Contrast (measured in all four themes with `getComputedStyle`): panel titles, labels, tab names, menu items and layer names are at least 4.5:1 (lowest: 5.97 for labels in Classic; 6.7 for selected layer names in Dark and Lime). Test: `tests/photoslop/theme-chrome.test.html`.
- In-app Theme menu (and the toolbar button): Pro is Dark, Light is Light, Paint '98 is Classic 98. `setTheme` (`js/ui/doc-dialogs.js`) saves the shared choice with `SlopTheme.set`, because Lime and Dark both map to `data-theme="pro"` and an app-only key could not tell them apart. Lime is chosen in Settings. At boot the shared script has already painted the choice, so `main.js` only repaints when the shared script is missing. `theme-color` is left to `brand/brand.js`.

## Colour (`shared/color/`, `js/ui/color-picker.js`, `js/tools/eyedrop.js`)
- **Colour state** is unchanged: `C.fg` and `C.bg` (`tools/state.js`), written only by `setColor(which, hex)`. A colour is `#rrggbb`, or `#rrggbbaa` when its alpha is below 1. Canvas fills, the brush tint and type use the alpha; `hexToRgb` reads RGB only, so colour range and hue jitter ignore it.
- **Shared with SlopVector** (`shared/color/`): `model.js` (`SlopColor`: hex with alpha, HSB, recent-list update, alpha-weighted box mean, box clipping) and `picker.js` + `picker.css` (`SlopColorPicker.create`: saturation-brightness square, hue and alpha bars, preview, hex / RGB / HSB / alpha fields, recent and palette rows). A person's change calls `onChange` at once; `set` is silent; `commit` records the colour in recents.
- **Picker** (`js/ui/color-picker.js`): `editSwatch('fg' | 'bg')` opens the dialog. Changes apply live (swatch and canvas), Cancel restores the starting colour, OK records it. Recents are `store` key `recentColors`, 12 entries, newest first. Entry points: click or right-click the fg/bg swatch; Window ▸ Foreground Colour… and Background Colour…; right-click a Swatches panel swatch ▸ Edit Colour…. `pickColorDialog(title, initial, live)` also serves the filter colour parameters and the type colour (no live update). The side panel uses `colorPicker(get, set)`. On phones the dialog is a bottom sheet (`cp-sheet`, `css/extras.css`); at 390 px there is no page scroll.
- **Shortcuts:** X swaps fg and bg, D sets the defaults (existing).
- **Eyedropper** (`js/tools/eyedrop.js`, key I): point, 3×3, 5×5 or 11×11 average (`Sample Size` on the options bar); `Sample Composite` or `Sample Layer` (`T.eyedrop.all`). The average weights each pixel by alpha, so an opaque box gives the plain mean. A click or drag sets fg; Shift sets bg. A fully transparent sample leaves the colour unchanged (toast). **Loupe:** while the tool is active, an 11×11 magnifier (9 px cells) shows the pixels under the pointer, outlines the centre pixel and gives its hex. The source is cached per history step (`sampleCanvas`), so hovering does not flatten the document again.
- **Alt on a painting tool** (`eyeAltSample`, called from `onPointerDown` in `core/view.js` before the tool's `down`): brush, pencil, eraser, bucket, gradient, blur, sharpen, smudge, dodge, sponge. Alt samples into fg, Alt+Shift into bg, and nothing is painted. Clone, heal and spot keep Alt for their source, and shapes keep Alt for "from centre".
- **Limits:** alpha lives only in the colour string; the layer's own opacity is separate. Brush hue jitter ignores alpha. The loupe and the samples read the flattened composite (visible layers) or the active layer; they do not read the live stroke in progress.

## Transform (`js/core/size.js`, `js/ui/size-dialogs.js`, `js/tools/transform.js`)
- **Image ▸ Image Size…** (Ctrl+Alt+I): width and height in px or %, a link toggle that keeps the aspect ratio, resampling (nearest, bilinear, bicubic) and a live preview with the new size. One step (`Image Size`). `imageSize(w, h, mode)` scales every layer, mask and text model; bicubic steps down in halves first.
- **Image ▸ Canvas Size…** (Ctrl+Alt+C): new width and height with the nine-position anchor grid. The new area is transparent, the background or foreground colour, white or black. A coloured area is one new bottom layer, `Canvas Fill`, that covers only the new area (other layers are untouched). `resizeCanvas(w, h, dx, dy, label, fill)`.
- **Rotate and Flip.** Image ▸ Rotate 90° Clockwise / Counter Clockwise, Rotate 180°, Flip Horizontal, Flip Vertical act on the whole document (`transformCanvas`, guides move with the pixels). Layer ▸ Rotate and Flip, Edit ▸ Transform and the layer right-click menu act on the active layer through `transformLayerQuick`, which uses nearest neighbour so pixels stay exact. Each is one undo step, named after the command.
- **Free Transform** (Ctrl+T, `TRANSFORM` in `tools/transform.js`): the box with eight scale handles, a rotate handle, drag inside to move, the proportion lock (chain-link toggle in the options bar and the Image Size link, on by default, kept per session) scales corners and edges uniformly, and Shift inverts it for one drag, Alt scales from the centre, Enter applies, Escape cancels. The options bar shows X, Y (centre), W and H (%), the angle and Interpolation (`TRANSFORM.interp`, kept between transforms), with Commit and Cancel. The pixels are drawn once with the matrix on commit (`transformSurface` → `setInterp`); apply is one step, `Free Transform`.
- **Idle box** (`tools/transform-idle.js`): the active layer's bounds (or the selection's) show the same handles and a rotate knob under every non-painting tool; a drag on a handle runs Free Transform, double-click inside starts it. The Move options have Transform and X/Y/W/H/∠ fields (each change one `Free Transform` step), and each Layers row has a transform button.
- **Arrow keys** nudge the layer 1 px, Shift+arrow 10 px, while the Move tool is active. Every item above is a SlopCmd command (menus register them automatically), so it can be rebound and found with ⌘K.
- **Not done:** Lanczos (the canvas offers only low and high quality, so bilinear and bicubic are the browser's two filters); physical units (cm, in), since documents have no print resolution, so the document unit is px; skew, perspective and warp; quick rotate or flip of a selection moves only the selected pixels; a Free Transform on a type layer rasterises it, as before.

## Type (`js/type/`, loaded right after `tools/fill.js`)
- **Bug fixed:** changing colour/font/size etc. never reached an existing type layer. The options bar only wrote `T.type` (tool defaults), the colour picker only wrote `C.fg`, and only the old textarea editor was ever restyled.
- **Model** (`model.js`): `L.text = { str, x, y, font, size, bold, italic, color, tracking, align, leading, aa, warp:{style,bend}, runs:[{s,e,o}] }`. The character keys are the base style; `runs` override them per character range (rich text). `normText` upgrades old records. `setTextStyle(t, s, e, patch)` restyles a range (an empty or whole range restyles the base). `renderTextCanvas` draws mixed styles per line, tracking (`letterSpacing`), leading (% of size), anti-alias (none/sharp/crisp/strong/smooth as alpha curves) and warp (arc, arch, bulge, flag, wave, rise, by column displacement).
- **Editing** (`edit.js`): a `contenteditable="plaintext-only"` box of styled spans (`data-o` = overrides). `teRead` reads text and runs back; `TE.sel` tracks the selection (kept while focus is in the options bar). The whole edit is one history step (`Edit Type`). `editTypeLayer(L)` edits with everything selected (double-click a type layer's thumbnail, Layer ▸ Edit Text).
- **Changing properties** (`props.js`): `setTypeProps(patch, final)`. While editing it restyles the selection (or all text); with a type layer selected it restyles the whole layer and commits once (`final=false` previews sliders/colour drags and commits after 600 ms). With the Type tool active, changing the foreground colour recolours the text. Controls: options bar (font, style, size + slider, colour, alignment, AA, Warp…) and a **Character** panel (adds tracking and leading). Warp Text… dialog previews; Cancel reverts with no history step.
- **Saving:** autosave stores every key in `LAYER_META` (`core/model.js`); PSDs carry it in a private layer block `SLmd` (`io/psd-meta.js`, UTF-8 JSON), so type stays editable after reopening. Photoshop sees the rendered pixels only. The PSD clipping byte is written and read (`L.clip`) and composited (see Masks below).

## Repair and Auto Enhance (`js/tools/heal.js`, `js/tools/redeye.js`, `js/filters/repair.js`, `js/filters/enhance.js`)
- **Healing Brush** (`heal`, key J; Clone Stamp's size, hardness, opacity, Aligned and Sample all layers; Alt-click sets the source). Each dab works on a snapshot of the layer taken at stroke start (doc space). Per dab: `high = source − normalised blur_small(source)` (texture without brightness, small radius ≈ 0.15 × brush radius) and `low = normalised blur_large(target)`, where the target counts only alpha-weighted pixels outside the brush circle (radius ≈ 0.5 × brush radius, three box passes ≈ gaussian). The healed colour is `low + high`, and the dab's falloff is the clone brush's. This is normalised convolution rather than a Poisson solve: it keeps the surroundings' brightness and colour and adds the source's texture, and it is cheap. A brush larger than about 240 px gets its centre from the ring's global mean, not a blur.
- **Spot Healing Brush** (`spot`, key J; no source). The same blend, with the source taken from the clean ring just outside the brush: each pixel inside the brush takes the target pixel the same distance beyond the edge along its radius (a mirror across the brush boundary). A uniform background therefore heals to exactly its own value.
- Both paint one buffered stroke: one history step (`Healing Brush` / `Spot Healing Brush`), respect the selection and the layer's opacity. The sources are snapshots, so a stroke does not heal from its own earlier dabs.
- **Red-Eye** (`redeye`, key J, and Filter ▸ Repair ▸ Red-Eye Removal…). Tolerance and darkening (`T.redeye`). A pixel is red when `r / max(1, (g+b)/2)` passes a threshold set by the tolerance (`2.4 − 1.2 × tol/100`, soft over 0.6), and bright pixels are weighted down (`(235 − luma)/55`), so catchlights stay. Red is pulled to `max(g, b)` and darkened by up to 80 % of the darkening amount. The tool corrects a drawn region (a click corrects a square of the tool size); the region and the selection both limit it. The filter runs through the normal filter path, so the selection limits it.
- **Auto Enhance** (Filter ▸ Auto Enhance…). The maths is `shared/retouch/tone.js` (the same as Auto retouch below), on a copy of the layer at most 256 px wide: white balance (iterated grey-world blended with white-patch, gains 0.6–1.6, clipping guard), levels from the 0.5 and 99.5 percentiles of the balanced luma (at least 16 levels), a midtone (gamma) exposure that cannot clip, and a vibrance lift that spares skin (`shared/retouch/skin.js`). The dialog shows red and blue relative to green. "Protect skin tones" switches the skin reduction off. The dialog's sliders hold the values (`filter-dialog.js`: the filter's `plist(base)`); "Reset to auto" restores them without closing; OK is one history step.
- Filter ▸ Repair lists the three tools and the red-eye filter; Filter ▸ Auto Enhance… is the top item. Tools have SlopCmd commands, options-bar controls and right-click items (the brush picker for the two healing tools, the red-eye filter for the red-eye tool).
- **Not done:** model-based texture invention on the device (Auto retouch's Remove object fills by PatchMatch; Edit with AI is the generative option, with the person's key); the Patch and Content-Aware Move tools; the Red Eye tool still works on a drawn region (Auto retouch finds eyes with shared/faces when face detection is on); healing across a different document or from a flattened source unless "Sample all layers" is on; a faster solver for very large brushes (a 240 px stroke takes about 1.5 s in headless Chromium).

## Auto retouch (`js/retouch/`, `shared/retouch/`, `css/retouch.css`)
On the device, no key. `js/retouch/boot.js` (boot) adds the menus and the commands; `js/retouch/tool.js` (boot) is the Remove
Object tool (key J); the rest loads on first use (`psRetouch()`). The maths is pure and shared (`shared/retouch/*.js`, UMD, Node
tests in `tests/node/retouch.test.mjs`): `core` (blurs), `skin` (one skin model, the mask, spot finding), `tone` (auto enhance),
`horizon` (tilt), `portrait` (frequency separation, whitening), `patchmatch` (content-aware fill, run in `inpaint-worker.js`).
- **Commands** (`psRetouchCommands`, args schemas; Ctrl+K, AI panel, macros, WebMCP, the Claude Code plugin): `ps.retouch.auto-enhance`
  (`auto_enhance`), `ps.retouch.portrait` (`portrait_retouch`), `ps.retouch.remove-object` (`remove_object`, the selection or
  x/y/width/height; `engine: 'ai'` opens Edit with AI), `ps.retouch.straighten` (`straighten`, angle detected when omitted),
  `ps.retouch.detect-tilt` (read-only). `ps.retouch.dialog` is Filter ▸ Auto Retouch… (also Image ▸ Auto Retouch…, and Image ▸
  Straighten… asks first).
- **Results are layers above the picture, one undo step each:** "Auto Enhance" (the enhanced visible picture); "Blemishes" (healed
  with the Spot Healing Brush's own `healStamp`, mask = the discs), "Skin Smoothing" (mask = skin), "Red Eye" (`redEyeData`),
  "Teeth Whitening", "Eye Whitening" (each with its mask); "Remove Object" (only the filled area, feathered). Straighten rotates
  every layer and mask and crops to the largest box of the same proportions (`straightenBox`).
- **Faces:** `shared/faces` (YuNet) is loaded on demand and used only when the person has turned face detection on (Profile);
  the dialog offers the shared opt-in. Without faces, skin comes from colour (and the optional subject matte, the portrait
  model of `shared/cutout`, behind the shared first-use notice); red-eye and whitening are skipped and the reply says so.
  With faces, skin is limited to the face, neck and shoulders, learnt from the cheeks; eyes, brows and mouth are cut out.
- **Blemishes:** small dark or red blobs in the skin (difference from a local blur, a noise-adaptive threshold), not longer
  than 2·maxR + 2 or more elongated than 2.5:1, on calm skin (the ring the heal reads must vary little), healed twice.
- **Remove object:** a crop around the area (at most 360 px across) is filled by PatchMatch, coarse to fine; the coarsest
  level matches on known pixels only. Over 12 % of the picture (or 45 % of a side) the tool asks: Fill on this device or
  Edit with AI (your key), with the trade-off said plainly. Big areas come out smooth on the device.
- **Workflows:** `shared/ops/retouch.js` registers `photoslop.auto-enhance` ("Auto enhance photos") and `photoslop.portrait`
  under PhotoSlop; they run the commands in the hidden PhotoSlop (`shared/macros/frame.js`), so there is one implementation.
- **Phones and touch:** the dialog is a bottom sheet under 640 px; the split view is a touch surface (drag or arrow keys);
  the Remove Object tool paints with a finger (it is in `BOX_HIDDEN_TOOLS`, so the layer box does not take the drag).
- Tests: `tests/photoslop/retouch.test.html` (cast, blemishes and edge, faces stub, remove, big area choice, straighten, undo),
  `retouch-dialog.test.html` (split view, Apply/Cancel, macro step, contrast in four themes, phone sheet),
  `retouch-touch.test.html` (touch runs), `tests/workflows/retouch.test.html` (three pictures), `tests/node/retouch.test.mjs`.
- **Limits:** the on-device fill copies texture, it does not invent structure (use Edit with AI for big or complex areas);
  skin smoothing and blemishes rely on colour when face detection is off, so warm backgrounds can count as skin (the
  subject switch or the layer masks fix that); red-eye needs visible eyes (sunglasses: nothing to fix).

## Guides, rulers, grid, snapping (`js/guides/`, uses `shared/guides/`)
- **Model** (`model.js`): `D.guides` is an immutable array of `{ o: 'v' | 'h', pos }` in document px. It is part of every history snapshot, so every guide change is one undo step (`setGuides(list, label)`, `addGuide`, `applyGuides(list, 'add' | 'replace')`, `clearGuides`). Tabs stash it; autosave stores it; PSD read/write uses image resource 1032, so Photoshop sees the guides. Canvas Size, Crop, Image Size and Image Rotation move the guides with the pixels (`remapGuides`).
- **View settings** live in `store` (`GUIDE_PREFS`): `guides`, `lockGuides`, `snap`, `snapTo.{guides,grid,bounds}`, `rulers`, `grid`, `gridSize`, `gridSub`, `gridColor`, `guideColor`.
- **Snapping**: `snapP(p, tool)` snaps pointer points for marquee, ellipse, polygonal lasso, crop, shape, gradient, type and transform handles (wired in `core/view.js`). `snapDelta(box, dx, dy)` snaps moving boxes by their edges and centre: Move tool (layer or floating selection), moving a selection, Free Transform move. Targets: guides, then document edges/centre, then the grid (guides win over the grid). `V.snapInd` draws the magenta indicator while dragging.
- **Drawing** (`overlay.js`): grid with dotted subdivisions, guides, the live layout preview (`V.guidePreview`), the drag pill, and the rulers (drawn on the view canvas, 18 px bands). `view.js` calls `drawGuidesLayer(g)` and `drawTopOverlays(g)`.
- **Input** (`input.js`): capture-phase pointer listeners on the viewport run before the tools. Drag from a ruler to make a guide; with the Move tool (or Ctrl/⌘ held) drag a guide to move it, drop it on a ruler or outside to delete; double-click or right-click a guide to edit/delete; Shift snaps to ruler ticks.
- **UI** (`ui.js`): View menu: Rulers (Ctrl+R), Grid (Ctrl+'), Grid Settings…, Show Guides (Ctrl+;), Lock Guides (Alt+Ctrl+;), Clear Guides, New Guide… (units: px, %, mm, in, pt), New Guide Layout… (Alt+Shift+Ctrl+;), New Guides from Shape, Snap (Shift+Ctrl+;), Snap To ▸. Window ▸ Guides opens the shared GuideGuide-style panel (`openGuidesPanel`) with Canvas / Selection / Layer bounds targets.

## Commands and shortcuts (`js/app/commands.js`, uses `shared/commands/`)

## Layer Style dialog, view rotation, effect preset picker (`js/ui/layer-style*.js`, `js/core/view-rot.js`, `js/layers/fx-preset-picker.js`)
- **Layer Style dialog** (`js/ui/layer-style.js`, pages in `layer-style-pages.js`): double-click a layer (thumbnail or row; a type layer still edits its text), or Layer ▸ Layer Style ▸ Layer Style…. Sections on the left: Blending Options (blend mode), Drop Shadow, Inner Shadow, Outer Glow, Stroke, Color Overlay, Gradient Overlay (each an effect with an enable switch; the controls are `FX_BY_ID` params through `paramControl`), and Opacity and Fill. A live preview of the layer sits on the right. Preview (on by default) shows the edits on the document while they are made; OK is one step (`Layer Style`); Cancel, Escape and × restore the layer with no step. Phone width: sections scroll sideways, the preview goes below.
- The FX rows (double-click, their edit button, Enter) and the right-click "Edit effect…" still open the per-effect `openFxDialog`, which the effects tests cover.
- **Fill** (`L.fillOp`, 0 to 1, in `LAYER_META` so autosave and PSD meta keep it): with no effect on, fill multiplies the layer's alpha like opacity (`layerAlpha`, `js/layers/fx.js`). With effects on it scales the layer's own pixels before the effects are drawn, so the effects fade too: an approximation of Photoshop, which keeps effects at full strength. Photoshop's own PSD fill byte is not written.
- **View rotation** (`js/core/view-rot.js`): `V.rot` in degrees, -180 to 180, per tab (`tabs.js`), never in the document, export or history. `V.ox`, `V.oy` and the zoom stay in unrotated view space; `draw()` rotates the context about the viewport centre (`rotateCtx`) and the brush preview and rulers are drawn outside it. Pointer input goes through `viewLocal` (used by `toDoc`, the guides, the idle box, the type editor's box, the wheel, pinch and nav) and `viewPt`/`viewDelta`; overlays with screen-space meaning use `hostPt`. Rulers show only at 0° (their ticks follow the unrotated axes); guides, grid and the page rotate.
- Controls: View ▸ Rotate View Left (Alt+[), Rotate View Right (Alt+]), Reset View (Alt+0). The viewport toolbar above the canvas has the same two buttons, a -180 to 180 slider, the angle and Reset View; the status bar shows ∠ when the view is turned. `[` and `]` are brush size, and Ctrl+0 is Fit on Screen, so rotation takes Alt. Reset View returns rotation, zoom and pan to the opening defaults (`fitView(true)`).
- **Effect preset picker** (`js/layers/fx-preset-picker.js`, `fxPresetPlan` in `fx-presets.js`): PhotoSlop's own dialog, not `SlopPresets.openPicker`, because it previews. Choosing a row puts its effects on the layer with no step; Apply writes them as `Apply Preset: <name>`; Close, Cancel and Escape restore the layer. Export, Import and Delete (confirmed) use the shared registry. Its styles are `css/presets.css` (the shared picker had none, so its rows showed as bare text).
- Tests: `tests/photoslop/preset-picker.test.html` (4), `layer-style.test.html` (7), `view-rotation.test.html` (6).

## Masks, clipping, Subject and layer styles (`js/layers/masks.js`, `js/tools/subject.js`, `js/filters/fx-more.js`, `js/core/composite.js`)
- **Layer masks.** A mask is `L.mask = { canvas, x, y, def, enabled }`: the canvas alpha is how much of the layer shows, `def: true` hides the area outside the canvas (Hide All), `def: false` reveals it. Layer ▸ Layer Mask (and the layers panel's mask button) add Reveal All, Hide All or Reveal Selection; paint on the mask with the brush (black hides, white reveals; the layers panel's mask thumbnail or `UI.editMask`); Disable / Enable Mask (Shift-click the mask thumbnail too); **Invert Mask** (`invertMask`, flips the alpha and `def`); Apply Mask (bakes it into the pixels); Delete Mask. Each is one history step. Masks are saved in the PSD (layer mask record), in autosave and in the PSD round trip test.
- **Clipping masks.** `L.clip = true` clips a layer to the nearest lower layer that is not itself clipped (`clipBase`). `compositeInto` takes the clipped layer's effects-included surface and keeps only where the base is opaque (`clipWith`); a clipped layer hides with its base, and the bottom layer cannot clip. `bakedLayer` applies the clip too, so Merge Down keeps the look. Create or release: Layer ▸ Create Clipping Mask (Alt+Ctrl+G, the label changes), the layer's right-click menu, or **Alt-click a layer row** (the row, not the gap between rows). Clipped rows show "↳ clipped".
- **Select ▸ Subject** (`selectSubject`). Runs the vendored on-device remover (`shared/cutout`, the fast model, `SlopCutout.removeBackground`) on the visible composite over white and makes its matte the selection (one step, `Select Subject`). If the model cannot run (no WebAssembly, a stopped worker, or model files that are missing), a colour-difference fallback selects what differs from the border average. Layer ▸ Layer via Cut (Shift+Ctrl+J) then moves the selection to a new layer and clears it from the original.
- **Layer styles.** The stack (`L.fx`) gained Inner Shadow, Inner Glow and Gradient Overlay (`fx-more.js`, same renderer contract as the others). Existing: Drop Shadow, Outer Glow, Stroke, Color Overlay, Bevel & Emboss (approximate). Rows show live labels, each change is one step, eye hides, Delete removes.
- **Not done:** Quick Select (only Subject and the wand); pattern overlay, satin, inner/outer bevel variants, contour and Bevel & Emboss shading as a true emboss; Subject uses the composite, not a layer's own alpha; clipping to a base's effects (the base's shadow is not clipped against); clipping groups (only single clipped layers, one base each).
- Tests: `tests/photoslop/masks.test.html` (14: masks, the brush on a mask, invert, toggle, delete, apply, PSD round trip; clipping and PSD; Subject with the model and the fallback, Layer via Cut) and `effects.test.html` (the new styles, one step each, hide and delete, live pixels, layer blend modes).

## Slop Drive (shared storage)

- **Save (Ctrl+S)** writes the layered PSD back to the Slop Drive file the tab was opened from (`CUR.driveId`, via `SlopHub.update`, falling back to `put` with the same id). The first save asks for a folder. `File ▸ Download as Photoshop (.psd)` keeps the old download; `Save PNG to Slop Drive` still adds a copy.
- **File ▸ Open from Slop Drive…**, `?drive=<id>` launch (`hubBoot` → `openRecordTab`, which links the new tab), and `SlopHub.register('photoslop')` on boot.
- Paint Classic (`classic/`): `hub.js` overrides `ACTIONS.save` (PNG written back to the linked Drive file) and adds `File ▸ Open from Slop Drive…`; it registers as `paint-classic` and opens `?drive=` launches. Offline and without `SlopHub`, Save downloads as before.

## Shape corners (`js/tools/shape-layer.js`, `shared/shapes/`)

- The Shape tool's Rectangle and Rounded Rectangle kinds have a Corner radius option (default 0; picking Rounded Rectangle sets 32 if it is 0). The path comes from `SlopShapes.canvasPath` (`js/tools/stroke.js` `shapePath`).
- A drawn rectangle is a shape layer: `L.shape = { kind, r, radius, fill, stroke, strokeW, fg, bg }` and its canvas is redrawn from it. Changing the option redraws the active shape layer. A slider drag is one history step (400 ms settle), and a typed value is one step.
- Painting, selecting, transforming or filtering a shape layer rasterizes it, as for type. Crop and resize drop the record and keep the pixels. Other kinds (ellipse, polygon, star, heart, line) are still plain pixels.
- Tests: `tests/photoslop/shapes.test.html`.
