Audit

Comment fonctionne Slopographic

Les applications tournent dans votre navigateur. Cette page liste les fonctions du navigateur qu’elles utilisent, chaque requête réseau qu’elles peuvent faire, et ce qui est gardé sur votre appareil, afin que vous puissiez vérifier chaque affirmation vous-même. Chaque énoncé de cette page a été contrôlé dans le code source du dépôt public.

La version courte

  • Vos fichiers restent sur votre appareil. Les applications n’ont pas de serveur qui les reçoive, et aucun code n’envoie un fichier que vous ouvrez ou enregistrez. Seule exception : une copie que vous autorisez le bouton IA à envoyer à un service d’IA que vous avez connecté vous-même.
  • Les fichiers que vous choisissez sur le disque sont lus et écrits par l’API d’accès aux fichiers du navigateur, dans les dossiers que vous sélectionnez. Voir les API du navigateur.
  • Les données sont gardées dans le stockage propre au navigateur, sur cet appareil (IndexedDB et localStorage). Voir ce qui est stocké.
  • Certaines requêtes quittent le site, mais seulement dans les cas listés dans chaque requête sortante : un téléchargement que vous confirmez, une sauvegarde dans le nuage que vous connectez, un service d’IA que vous connectez avec votre propre clé, les taux de change que vous activez, ou les statistiques ou publicités que vous acceptez.
  • Le bouton IA fonctionne avec un modèle sur votre appareil, un serveur sur votre propre ordinateur comme Ollama ou LM Studio, ou votre propre clé pour un service comme Claude, ChatGPT ou Gemini. Avec une clé, ce que vous demandez va directement de votre navigateur à ce fournisseur. Voir le bouton IA.
  • La page d’accueil charge le code de Google Analytics à chaque visite, avec les statistiques réglées sur refusées. Les autres pages ne le chargent qu’après que vous avez accepté les statistiques. Les publicités ne se chargent qu’après que vous les avez acceptées.

En termes simples

Où vont mes fichiers ?

Nulle part. Quand vous ouvrez une photo, un PDF ou un tableur, l’application le lit dans cet onglet du navigateur. Il n’y a pas d’étape d’envoi, ni de serveur Slopographic qui pourrait le recevoir. Ce que vous enregistrez va sur votre propre disque, ou dans le stockage de ce navigateur, sur cet appareil. Une copie n’est envoyée à un service d’IA que si vous connectez ce service avec votre propre clé, et si vous l’autorisez (voir le bouton IA).

Pourquoi une application télécharge-t-elle parfois quelque chose ?

Certaines fonctions ont besoin d’un gros fichier que la plupart des gens n’utilisent jamais : un modèle d’IA (pour supprimer un arrière-plan, lire du texte ou transcrire la parole), le moteur vidéo (pour convertir une vidéo), ou une police pour un autre système d’écriture. Ces fichiers ne sont récupérés que lorsque vous utilisez la fonction, après que l’application vous a dit ce que c’est et quelle en est la taille, et ils sont gardés dans le navigateur, si bien que cela n’arrive qu’une fois. Vos propres fichiers ne font jamais partie de cette requête.

Fonctionne-t-il hors ligne ?

Oui, après la première visite. Les fichiers propres au site sont gardés par le navigateur, si bien que les applications s’ouvrent et fonctionnent sans connexion. Seul un téléchargement que vous n’avez pas encore fait (un modèle ou une police) a besoin du réseau.

Faut-il installer quelque chose ?

Non. Ouvrez simplement une application dans le navigateur de votre téléphone, de votre tablette ou de votre ordinateur, et commencez. Elle continue de fonctionner sans internet après votre première visite. Vous voulez une icône sur votre écran d’accueil ? Sur iPhone ou iPad, touchez Partager, puis Sur l’écran d’accueil. Sur Android, ouvrez le menu du navigateur et touchez Ajouter à l’écran d’accueil. Sur un ordinateur, cliquez sur l’icône d’installation dans la barre d’adresse. Vous n’avez besoin ni de l’App Store ni de Google Play, et vos fichiers restent sur votre appareil.

Qu’envoie le bouton IA, et où ?

Cela dépend du modèle que vous choisissez. Un modèle sur votre appareil (il demande WebGPU et se télécharge une fois) répond dans cet onglet, et rien de ce que vous demandez ne quitte l’appareil. Ollama, LM Studio et les serveurs semblables tournent sur votre propre ordinateur, ou sur un ordinateur de votre réseau que vous avez configuré. Avec votre propre clé pour un service comme Claude, ChatGPT, Gemini, OpenRouter ou Groq, vos messages vont directement de votre navigateur à ce fournisseur, sans serveur Slopographic entre les deux, et ses conditions et ses tarifs s’appliquent. Une copie d’un fichier ou une image de votre travail n’est envoyée qu’après que le panneau le demande et que vous l’autorisez (vous pouvez l’autoriser pour une requête, pour une visite, ou toujours, et retirer cette autorisation dans Autorisations IA). Les images créées ou modifiées par l’IA (Générer une image, Modifier avec l’IA) ont besoin d’un service d’images que vous connectez, comme OpenAI, Gemini ou OpenRouter avec votre propre clé : rien dans le navigateur ne les dessine. Les modèles sur votre appareil et sur votre propre ordinateur ne coûtent rien ; Gemini, Groq et Mistral ont des offres gratuites, et OpenRouter propose des modèles gratuits (le panneau les marque Gratuit). Une clé est gardée dans cet onglet jusqu’à sa fermeture, ou dans ce navigateur seulement si vous cochez Mémoriser sur cet appareil. Pour OpenRouter, vous pouvez aussi appuyer sur Se connecter avec OpenRouter au lieu de coller une clé : votre navigateur va sur openrouter.ai, vous y autorisez l’accès, et au retour, cette page demande à OpenRouter lui-même une clé pour ce navigateur. La connexion passe directement entre votre navigateur et OpenRouter, et rien ne transite par les serveurs de Slopographic. La clé est payée avec vos propres crédits OpenRouter et est gardée exactement comme une clé collée ; vous pouvez la plafonner ou la révoquer sur openrouter.ai/settings/keys, et Oublier la clé la retire de ce navigateur.

Un agent d’IA peut-il utiliser les applications ?

Dans un navigateur qui prend en charge WebMCP, oui : un assistant du navigateur, ou un agent sur votre ordinateur connecté par une extension du navigateur, peut lancer les commandes d’une application, les conversions et les flux de travail de File convert, et ouvrir, enregistrer ou télécharger des fichiers. Il désigne vos fichiers par des identifiants ; le travail se fait dans cet onglet et les applications n’envoient rien, même si l’agent voit ce que les outils renvoient. Toute action qui supprime ou remplace votre travail vous demande d’abord votre accord. WebMCP est un brouillon précoce : Chrome l’a en essai (versions 149 à 156) et derrière un indicateur, Edge derrière un indicateur, et Firefox et Safari pas encore. Désactivez-le dans Paramètres, ou dans Aide, Agents IA.

Puis-je le vérifier moi-même ?

Oui. Le code source est public, et les sections ci-dessous listent chaque fonction du navigateur que les applications utilisent et chaque requête qu’elles peuvent faire, avec le fichier qui la fait. Vous pouvez aussi ouvrir les outils de développement de votre navigateur, aller dans l’onglet Réseau et observer : ouvrir et enregistrer vos fichiers n’envoie rien.

Utiliser Slopographic depuis Claude Code et d’autres applications d’IA

Bientôt disponible : une application d’IA sur votre ordinateur, comme Claude Code, Codex, Cursor, VS Code ou Claude Desktop, peut utiliser l’application Slopographic ouverte dans votre navigateur : ses vraies commandes, conversions et flux de travail, vos fichiers entrant et les résultats sortant sous forme de fichiers sur votre ordinateur. Cela passe par le serveur MCP de Slopographic, un petit programme que l’application d’IA lance sur votre ordinateur. Aucun compte ni aucune installation n’est nécessaire, en dehors de l’application d’IA elle-même.

  1. Claude Code : tapez /plugin marketplace add slopographic/claude-plugin, puis /plugin install slopographic@slopographic. Une seule fois suffit.
  2. Tapez /slopographic:slop-connect (ajoutez un nom d’application, comme photoslop, si vous voulez). Claude Code ouvre Slopographic dans votre navigateur et affiche un court code.
  3. Chrome demande une fois si ce site peut utiliser les applications et services de cet appareil. Choisissez Autoriser : c’est ainsi que la page atteint Claude Code sur votre ordinateur. La page ne parle qu’à votre propre ordinateur (127.0.0.1), et non à votre réseau.
  4. Tapez le code dans la page. La page affiche alors « Claude Code est connecté · Déconnecter » dans le coin. Appuyez sur Déconnecter, ou fermez l’onglet, pour mettre fin à la connexion.

Chaque onglet est appairé séparément, et le code ne fonctionne qu’une fois. Rien d’autre sur votre ordinateur ne peut utiliser la page sans lui. Les actions qui suppriment ou remplacent votre travail vous demandent toujours confirmation dans la page, comme dans le panneau IA. Toute page Slopographic peut se connecter depuis la palette de commandes : Ctrl+K (⌘K sur un Mac), puis « Connecter une application d’IA… ».

La configuration pour d’autres applications d’IA (Codex, Gemini CLI, Cursor, VS Code, Windsurf, Claude Desktop) apparaîtra ici lorsque les scripts seront prêts.

Les conversations ChatGPT ne peuvent atteindre que des serveurs sur internet ; elles ne peuvent donc pas encore utiliser ce serveur local. Codex dans l’application de bureau ChatGPT, lui, le peut.

Cookies et statistiques

  • Stocké par le code du site : un choix de consentement dans localStorage (slop-consent), avec les statistiques, les publicités et les taux désactivés jusqu’à votre choix. Le stockage peut être effacé dans le navigateur à tout moment.
  • Non stocké par le code du site : ni cookie ni compte. Le dépôt n’écrit jamais de cookie.
  • Google Analytics : sur la page d’accueil, la balise est chargée avec analytics_storage réglé sur refusé. Elle n’est activée que lorsque vous acceptez les statistiques. Sur les autres pages, elle ne se charge qu’après votre acceptation.
  • Les scripts propres à Google peuvent poser leurs propres cookies quand ils tournent. Cela relève de Google, et non du code de Slopographic. Les étapes de vérification ci-dessous montrent ce que le navigateur stocke réellement.
  • Publicités : AdSense ne se charge qu’après que vous avez accepté les publicités. Refuser les publicités laisse les emplacements publicitaires vides.

Travailler hors ligne

Après une visite, les fichiers propres au site sont gardés dans Cache Storage par le service worker (service-worker.js, avec sa liste de fichiers dans sw-precache.js). Les pages sont d’abord demandées au réseau, puis prises dans le cache, et enfin la page hors ligne s’affiche. Vos fichiers ne sont pas dans le cache du service worker : ils sont dans le dossier que vous avez choisi, ou dans IndexedDB. Les applications continuent de fonctionner avec le réseau coupé. Les téléchargements (les modèles et paquets de polices listés plus haut) ont besoin du réseau la première fois.

Comment le vérifier vous-même

  1. Onglet Réseau, avec la page chargée. Ouvrez l’application, appuyez sur F12 (ou Cmd+Option+I sur un Mac), et ouvrez l’onglet Réseau. Cochez « Conserver le journal », puis rechargez. Lisez la colonne Domaine. Lors d’une visite simple, vous ne devriez voir que slopographic.com, plus les domaines d’analyse de Google sur la page d’accueil.
  2. Onglet Réseau, hors ligne. Dans l’onglet Réseau, ouvrez le menu de limitation et choisissez Hors ligne. Rechargez, puis ouvrez un fichier, modifiez-le et enregistrez-le. L’application doit fonctionner. Tout ce qui demande un téléchargement l’indique.
  3. Onglet Application, stockage. Dans Chrome ou Edge, ouvrez l’onglet Application. Sous Stockage, regardez Stockage local, Stockage de session, IndexedDB, Cookies, Cache Storage et Service workers. Comparez ce que vous voyez avec les tableaux de cette page.
  4. Accepter ou refuser, puis comparer. Refusez les statistiques et les publicités dans la bande de consentement, rechargez, et revérifiez l’onglet Réseau. Acceptez-les ensuite, et voyez quelles requêtes apparaissent.
  5. Lire le code source. Le code est public dans le dépôt slopographic sur GitHub. Cherchez-y fetch(, indexedDB.open, localStorage ou showDirectoryPicker pour confirmer une ligne de cette page. Le code du consentement est dans shared/consent/, la synchronisation dans le nuage dans shared/sync/, et les listes de téléchargement dans shared/library/ et aitools/.

Les dossiers locaux (l’API d’accès aux fichiers) nécessitent Chrome ou Edge. Firefox et Safari ne les proposent pas, et les applications le signalent là où c’est pertinent.
