# SEO handoff

Every page the site ships has a static SEO head: title, description, canonical, Open Graph, Twitter
tags and JSON-LD. It is written into the HTML by a Node tool, not built at run time, so crawlers
see it without running JavaScript. The site still has no build step: you run the tool by hand
after changing copy or the app list.

## Files

- `shared/apps.js`: the registry. Every app's id, name, `path` (folder, or `#anchor` for an app shown
  on the homepage), and optional `shot` (its image). Read by the generator, not edited by it.
- `shared/seo/i18n/<code>/<part>.js`: the copy, in string tables, English the source (`shared/seo/i18n/README.md`:
  the keys, the parts, the rules and the translators' brief). The `.mjs` files in `shared/seo` hold the facts
  (`copy.mjs`: which pages have copy and each app's `category`; tasks, roundups, guides: slugs, sources, dates, marks)
  and give the copy joined with them, in English (`HOME`, `APPS`, `ABOUT`, `TASKS`...) or in a language
  (`homeIn(code)`, `appsIn(code)`, `tasksIn(code)`...).
- `tools/seo/write.mjs`: writes the block into each page and rebuilds `sitemap.xml`.
  `node tools/seo/write.mjs` writes; `node tools/seo/write.mjs --check` fails if anything is out of date.
- `tests/seo/seo.test.mjs`: checks the HTML on disk. Run with `node tests/run.mjs seo`.

## What the tool writes

Each page gets one block, placed after its `<meta charset>` tag and marked
`<!-- seo:start -->` ... `<!-- seo:end -->`. The tool removes any old title, description, canonical,
`og:*`, `twitter:*` and `application/ld+json` tags first. It adds `lang` to `<html>` and a viewport
tag only when they are missing. Nothing else in the page changes.

- Every app page: `SoftwareApplication` (name, applicationCategory, operatingSystem
  "Any (runs in a web browser)", offers price 0 USD, description, url, author Slopographic) and
  `BreadcrumbList` (Home > App).
- About pages: `BreadcrumbList` (Home > App > About).
- Homepage: `Organization`, and an `ItemList` of every app in the registry (anchor apps included).
- Open Graph and Twitter image: the app's `shot` when that file exists, else `og-share.png`.
- `sitemap.xml`: the homepage, every app page, every about page, and the converter pages already
  listed. `lastmod` is today's date (or `--date=YYYY-MM-DD`).

Descriptions must be 120 to 160 characters, and titles and descriptions must be unique across the
site. The tool refuses to write otherwise.

## Adding a new app

1. Add the app to `shared/apps.js` with `path: 'name/'`. Add `shot: 'assets/shots/name.jpg'` if you
   have a screenshot. Without one, the share image is `og-share.png` (1200 x 630, rendered by tools/og/render.mjs).
2. Add the app's category to `CATEGORY` in `shared/seo/copy.mjs` (`name: 'BusinessApplication'`) and its title and
   description to `shared/seo/i18n/en/copy.js` (`'seo.app.name.title': 'Name: short hook in your browser | Slopographic'`,
   `'seo.app.name.description'`), and to every other language's `copy.js`.
   The category is a schema.org `applicationCategory` value (for example `MultimediaApplication`,
   `DesignApplication`, `UtilitiesApplication`, `DeveloperApplication`).
3. Make the page `name/index.html`, with `<html lang="en">`, `<meta name="viewport">` and
   `<meta charset="utf-8">`. Leave out the SEO tags, since the tool writes them.
4. If the app has an about page, write it as a template, `shared/seo/pages/about/name.html` (copy another one: the page's
   HTML with every sentence a `{{key}}`, `tools/seo/template.mjs`), put its words in `shared/seo/i18n/en/about-*.js`
   (`seo.aboutpage.name.*`) and every other language's, add its id to `ABOUT_IDS` and `seo.about.name.title` and
   `.description` to the tables. The tool writes `name/about/index.html` and its copies; it throws if an about page has no
   entry.
5. Run `node tools/seo/write.mjs`, then `node tests/run.mjs seo`.

An app on the homepage only (path `#something`) needs no page. Add it to `shared/apps.js` and it
appears in the homepage `ItemList`. Run the tool again after you change the registry.

## The header icon (brand/brand.js)

On app pages, the header brand link (`header a.brand`) shows that app's own icon from
`shared/app-icons.js` (`window.SLOP_ICONS`, keyed by app id). The Slopographic mark sits in the
corner as a small badge. The app id comes from `data-app` on the page's theme script tag
(`<script src="../shared/theme/theme.js" data-app="name">`). To give an app its icon, add one entry
to `SLOP_ICONS` (48 by 48 line art). Apps without an entry keep the Slopographic mark. Pages without
an `a.brand` link are not changed.

## Gotchas

- The seo tags are static HTML. If the copy changes, run the tool again. Do not edit the head by hand.
- `shared/seo/copy.mjs` and `tools/seo/write.mjs` are for Node only. Browsers do not load them.
- The service worker precache list is generated by `tools/pwa-precache.mjs`. Run it and bump the
  version after changing shared files that pages load at boot.

## Landing pages (/apps/<id>/, /slop-365/, /creative-slop-pro/, /compare/)

`tools/seo/landing.mjs` builds one landing page per app page in the registry, plus the Slop 365 hub,
the Creative Slop Pro page and the `/compare/` matrix. The body comes from `shared/apps.js` (H1 is the
registry `title`, the feature matrix is the registry `features`, file types come from `accepts`), so
edit the registry, not the page. The head copy is `LANDING` in `shared/seo/copy.mjs`. `node tools/seo/write.mjs`
writes the bodies and their head blocks and the sitemap, and `--check` verifies them. Tests: `tests/seo/seo.landing.test.mjs`.
A clip's `<video>` and a screenshot's `<img>` get the width and height of their picture (`assets/shots/<id>.jpg`, read by
`tools/seo/jpeg-size.mjs`; the shots come in many sizes), so nothing below moves when the poster loads.

## The footer navigation (tools/seo/footnav.mjs)

One block of plain links at the foot of the homepage, every page written with `shell()` (landing, task, round-up, guide,
hub, compare, how-it-works) and every converter page (`convert/js/core/pages.js`): the apps by registry group (each
`/apps/<id>/`), Compare (`/compare/`, `/best/` and every round-up), Converters (the first page of each converter category,
and `/convert/`), and Guides & help. It is built from the same data as the pages, so a new app, round-up or converter
category is linked the next time `node tools/seo/write.mjs` runs; nothing is listed by hand. The homepage carries it between
`<!-- site:footnav -->` markers; the converter pages get those markers in a `<footer class="cv-foot">` before their shell
script. Styles: `shared/footnav/footnav.css` (columns open on wide screens; folded `<details>` on phones). The app pages
do not get it. Tests: `tests/seo/footnav.test.mjs`, `tests/home/footer-nav.test.html`.

## Languages (tools/seo/lang.mjs)

Every static SEO page is written in every published language, each its own page for search engines:

- **URLs.** The root language (the brand profile's `defaultLang`: English here) is at the site root (`/compare/`,
  `/pdf/`). Every other published language has a folder with the same paths (`/sv/compare/`, `/sv/pdf/`,
  `/sv/convert/jpg-to-png/`, `/sv/`). Slugs stay the same in every language, so one path is one page in every language.
- **Which languages.** A language is published when its SEO tables are complete (`shared/seo/i18n/<code>/`, every English
  key) and the profile lets it in (`seo.langs`: `'all'`, the default, a list such as `["sv", "de"]`, or `'none'` / `[]`
  for the root language only; brand/README.md). A language without tables is not written at all: no English pages in its
  folder and no hreflang to it. `write.mjs` prints the languages it built and why the others were left out. A language
  folder holds only what `write.mjs` writes; it removes the rest.
- **Written on publish, never committed.** Only the root language's files are in git. The other languages' folders
  (`/sv/`) and their sitemaps (`sitemap-sv.xml`) are written when the site is published, and git ignores them: a block in
  `.gitignore` between `# seo:langs:start` and `# seo:langs:end`, written by `write.mjs` from the language list, anchored
  to exactly those names (`/sv/`, `/sitemap-sv.xml`; never `pdf/` or `docs/`). `tools/seo/langdirs.mjs` keeps it, and
  `write.mjs` refuses to write a language whose folder is an app's or not one it wrote. The modes:
  `node tools/seo/write.mjs` (the root language: the committed files, and the block), `--langs` (the other languages
  only: about 10 seconds a language), `--all` (both); `--check` with any of them. Who runs `--langs`: the production
  deploy (`.github/workflows/pages.yml`), the preview (`preview.yml`), CI before the Node tests (`rules.yml`) and the
  pre-push hook, since the tests read the pages; a white-label build runs `--all` and commits them in its mirror
  (`tools/whitelabel/build.mjs`). For a local look at `/sv/`, run `--langs` (the folders stay out of git). With
  `seo.langs: 'none'` none of this builds anything.
- **The generated pages** (landing, task, guide, round-up and hub pages) are drawn in the language (`L`, a `lang.mjs`
  context: `L.t('seo.ui.*')` for the templates' own words); their links to another page that exists in the language
  go to that language's page.
- **The hand-made pages** (each app page, the homepage, the converter pages) get a copy in each language's folder
  (`copies.mjs`): the same HTML with `<base href>` pointing back at the original folder, so the app's own scripts and
  files load from where they are (nothing is duplicated but the page), the head in the language, the text of every
  `data-i18n` element filled from that language's tables (so a crawler reads it without scripts), and a converter
  page's own copy from `seo.cv.*`. GitHub Pages has no rewrites, so a real file must be at `/sv/pdf/`; a redirect page
  would not be indexed as the language's page, and the app reading the prefix itself would need a server.
- **The about pages and How it works** are templates (`shared/seo/pages/`, `tools/seo/template.mjs`): the page's HTML with
  every sentence a `{{key}}` of the tables (`about-*`, `how`). They are drawn in each language, the root one written at the
  page's own folder (`pdf/about/index.html`) and the others as copies like the hand-made pages; edit the template and the
  tables, never the written page. The typeface page is written by hand in English (its script writes English too) and
  stays in the root language only.
- **The head.** Every page that exists in more than one language lists them all with `<link rel="alternate" hreflang>`
  and `x-default` (the root language's page); the canonical is the page's own URL in its language. A hand-made page that
  keeps its own head (most converter pages) gets the alternates alone, between `<!-- seo:alt -->` markers.
  `<html lang>` (and `dir="rtl"` for Arabic and Hebrew) is written in the HTML, with `data-lang-page`: shared/i18n
  starts that page in its language (from the first frame: shared/i18n/early.js fills the marked text as it is parsed;
  tests/node/first-paint-page-lang.test.mjs), keeps a language other than the default as the visitor's choice, and the header's
  language switcher goes to the same page in the language picked (its alternate) when there is one.
- **Sitemaps.** `sitemap.xml` is the root language's pages, `sitemap-<code>.xml` each other language's, and
  `sitemap-index.xml` lists them all; robots.txt names `sitemap.xml` and the index. `sitemap.xml` and the index are
  committed; a language's sitemap is written with its folder, each page dated as the same page in `sitemap.xml`.
- **Checks.** `write.mjs` refuses copy that breaks the rules in any language: description lengths by script
  (`head.mjs` `descLimits`: 120 to 160 for Latin and most scripts, 45 to 110 for Chinese and Japanese, 55 to 130 for
  Korean), titles of at most 75 characters, titles and descriptions unique within a language.
  `node tools/i18n/i18n.mjs --check` holds the SEO tables like every other table (`todo seo <code>` lists what a
  language lacks, `coverage` reports them). Tests: `tests/seo/lang.test.mjs`, `tests/seo/lang-pages.test.mjs`.
- **Size.** Each published language adds about 560 pages (14 MB of HTML, none of it in git) and 1.1 MB of tables. None of it is precached by the service worker: the precache list follows the app pages' own boot files only.
